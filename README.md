# tt

Таск-трекер над markdown-vault. Источник правды — файлы `tasks/<project>/*.md`
с YAML-фронтматтером; `tt` их читает и правит по одному ключу за раз.

Заменяет файловые Kanban-доски Obsidian и обратный синк на них: доска перестаёт быть
файлом и становится представлением, которое строится из фронтматтера в момент показа.
Синхронизировать нечего — второго хранилища статуса не существует.

## Сборка

Веб-бандл (`web/dist`) вшивается в бинарник через `go:embed`, поэтому фронт
собирается **первым**:

```bash
cd web && npm install && npm run build && cd ..
go build -o tt.exe ./cmd/tt
```

Если пропустить `npm run build`, `go build` всё равно пройдёт — в git лежит
заглушка `web/dist/index.html` — но `tt serve` покажет её вместо настоящей
страницы. Обратный порядок тоже не спасает: `go build` вшивает то, что лежит
в `web/dist` **на момент сборки**, так что правки фронта без пересборки
бинарника не видны.

Go-зависимостей три: `gopkg.in/yaml.v3`, `github.com/fsnotify/fsnotify` и
`golang.org/x/sys` (транзитивная). На выходе один статический бинарник.

## Команды

```
tt list   [--vault ПУТЬ] [--project ИМЯ] [--status СТАТУС] [--json]
tt new    [--vault ПУТЬ] --project ИМЯ --title ТЕКСТ [--priority high|medium|low]
          [--effort 2h] [--depends-on ID,ID] [--spec ПУТЬ]
tt set    [--vault ПУТЬ] [--agent ИМЯ] ID КЛЮЧ [ЗНАЧЕНИЕ]
tt claim   [--vault ПУТЬ] [--agent ИМЯ] ID
tt release [--vault ПУТЬ] ID
tt reset   [--vault ПУТЬ] ID
tt doctor [--vault ПУТЬ] [--fix]
tt serve  [--vault ПУТЬ] [--port N] [--listen АДРЕС] [--agent ИМЯ]
```

Путь к vault берётся из `--vault`, иначе из `TT_VAULT`. Пути по умолчанию нет намеренно:
молча писать в чужой каталог хуже, чем потребовать один флаг.

`--status` понимает исторические написания: `--status in-progress` находит и таски
с `status: in_progress`.

`tt set` меняет одно поле. Смена статуса дополнительно проставляет `completed`/`ready_at`
и снимает `claim` с замком по правилам схемы. Незнакомый ключ отклоняется: иначе опечатка
тихо добавила бы во фронтматтер мусорное поле.

`tt claim` берёт таску в работу: проверяет переход, ставит замок и пишет блок `claim`
с полями `agent`, `host`, `branch`, `started`. `host` — имя машины, `branch` — текущая
ветка репозитория проекта (поле `repo` в `projects/<project>.md`); репозиторий недоступен —
поле остаётся пустым, а не выдумывается. Повторный `claim` своим же агентом законен,
чужой — отклоняется.

`tt release` отдаёт таску обратно в `ready`, снимая claim и замок. `tt reset` расклинивает
залипшую таску после упавшей сессии: снимает замок и claim даже чужие и засчитывает
попытку в `attempts`. Замена `/work --reset`.

`tt doctor` без `--fix` только отчитывается. Починяемые проблемы помечены `*`.

`tt serve` строит индекс, следит за vault на изменениях и поднимает веб-доску по
HTTP (`GET /api/snapshot`, `GET /api/task/{id}`, `GET /api/events` — SSE,
`POST /api/task/{id}/status`) плюс отдаёт сам фронт из `web/dist`. Порт по
умолчанию — `4173`; занят — понятная ошибка вместо паники. Ctrl+C гасит и
HTTP, и вотчер. Сама доска на этом этапе — заглушка (заголовок и число
тасок); полноценный UI — отдельная задача.

## Гарантии записи

- Меняется **ровно один ключ** фронтматтера; остальные байты файла не трогаются.
  Закреплено тестом: diff после смены статуса — ровно одна строка.
- Никакого round-trip через YAML-библиотеку: она переставила бы ключи и потеряла пустые
  значения, превратив git-diff в мусор.
- Запись атомарна: временный файл в том же каталоге плюс `rename`.
- CRLF, BOM и порядок ключей сохраняются; значения с `": "` закавычиваются при записи.
- Правка идёт под замком `.locks/<ID>.lock` — тем же, что берут bash-агенты.

## Замок

`.locks/<ID>.lock` — **не мьютекс на время команды, а долгоживущий признак «таска
в работе»**, парный статусу `in-progress`. Ставится при взятии в работу, снимается при
уходе из него, переживает и команду, и процесс. Упавшая сессия оставляет замок —
авто-снятия нет намеренно, сброс ручной. `tt doctor --fix` убирает осиротевшие.

## Правила флоу

Живут в `<vault>/.task-tracker/schema.json`: статусы, порядок и подписи лейнов,
исторические написания, что проставлять при переходе и когда снимать claim. Этот файл —
общий контракт для будущей веб-доски и плагина Obsidian, поэтому добавленный лейн
появится на обеих досках без правки кода. Если файла нет, используется встроенная копия.

Полной матрицы переходов нет сознательно: перетаскивание карточки между лейнами законно
почти всегда. Стерегутся два случая — взять в работу таску с живыми `blocked_by`
и отобрать чужой claim.

## Состояние

Этапы 1–3 завершены: чтение и запись, `list` / `set` / `doctor`, плагин Obsidian,
`tt serve` с веб-доской — лейны, перетаскивание, живое обновление по SSE, панель
таски, страница «Пульс», доступ по локальной сети с токеном на запись.

Дальше по спеку — этап 4: `tt new` / `claim` / `done` / `next`, перевод слеш-команд
на `tt` и снос замещённых bash-скриптов.

Замеры на живом vault из 1300 тасок:

| | |
|---|---|
| бинарник | 10.9 МБ |
| веб-бандл | 56 КБ JS + 6 КБ CSS |
| `tt serve` до первого ответа | 580–600 мс |
| снимок для браузера | 384 КБ |
| память процесса | 22 МБ RSS |

Рост бинарника с 5.0 МБ дал не бандл, а линкер: следом за `http.Server` подтягиваются
`crypto/tls`, `x509` и `http2`, даже когда TLS не используется.

Известные ограничения:

- `tt set X status in-progress` замок ставит, но блок `claim` не пишет: владельца
  фиксирует только `tt claim`.
- Таски с непарсящимся фронтматтером не видны ни на веб-доске, ни в плагине — их
  показывает `tt doctor`. В живом vault таких 31.
- `go test -race` на машине разработки недоступен: детектор гонок требует CGO,
  а `CGO_ENABLED=0` и нет C-компилятора.

## Тесты

```bash
go test ./... -count=1
go vet ./...
```

Смоук по живому vault (только чтение, копии правятся во временном каталоге):

```bash
TT_SMOKE_VAULT="D:/task tracker" go test ./internal/vault/ -run TestLiveVault -count=1 -v
```
