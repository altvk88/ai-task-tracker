# System Patterns

## Architecture

```
              .task-tracker/schema.json  (статусы, лейны, правила)
                        |                        |
  Go-бинарник tt                                       Плагин Obsidian (TS)
  ├─ model    правила флоу, без I/O                    ├─ metadataCache (чтение)
  ├─ vault    единственный код, трогающий ФС           └─ processFrontMatter (запись)
  ├─ index    снимок в памяти + подписчики (этап 3)
  ├─ server   HTTP + SSE + go:embed(Svelte) (этап 3)
  └─ cli      list / set / doctor / serve
                        |                        |
                        +-> tasks/<project>/*.md <+
```

| Пакет | Обязанность | Не знает про |
|---|---|---|
| `model` | Task, схема, guard'ы, промоут | файловую систему, HTTP |
| `vault` | markdown, фронтматтер, замки, атомарная запись | HTTP, CLI, правила флоу |
| `index` | снимок в памяти, события fsnotify, рассылка | HTTP-протокол |
| `server` | запрос → model+index → JSON, SSE, статика | markdown |
| `cli` | подкоманды над теми же пакетами | HTTP |

Проверка границ: `model` тестируется таблицей без временных каталогов, `vault`
компилируется без `server`. Если тесту переходов понадобился каталог — границы поехали.

## Key design decisions

**Доска не файл.** Единственная причина всех прежних проблем — второе хранилище статуса.
Его больше нет, поэтому нечего сверять: удалены не только доски, но и весь класс защит
вокруг синка (sanity-гейт, bulk-guard, dry-run, процедура восстановления).

**Запись только хирургическая.** Никакого round-trip файла через YAML-библиотеку: она
переставит ключи и потеряет пустые значения, превратив git-diff в мусор. Меняется одна
строка, остальные байты не трогаются. Закреплено тестом: diff после смены статуса — ровно
одна строка.

**Атомарность через tmp + rename** в том же каталоге: `os.Rename` на NTFS внутри каталога
атомарен, прерванный запуск не может оставить недописанный файл таски.

**Кавычки ставит писатель, а не хук после факта.** Незакавыченное значение с `": "` ломало
парсер Obsidian; раньше это лечил `tt-quote-fm.sh` постфактум. Теперь лечить нечего.

**CRLF и BOM терпим с первого дня**, а не после инцидента: vault лежит на Windows,
Obsidian пишет CRLF, `core.autocrlf=true`.

**Правила флоу — в данных, не в двух кодовых базах.** `schema.json` читают и Go, и плагин.
Добавленный лейн появляется на обеих досках без правки кода.

**Guard'ы вместо матрицы переходов.** Полная таблица 10×10 никому не нужна: перетаскивание
карточки законно почти всегда. Стерегутся два реальных случая — взять в работу таску с живыми
`blocked_by` и отобрать чужой claim. Доска не должна спорить с человеком.

**Битое не проглатывается молча.** Непарсящаяся таска возвращается с `ParseErr` и попадает
в лоток «Broken» — прежние скрипты такие файлы просто пропускали, и они терялись.

**Замок общий с bash.** `mkdir <vault>/.locks/<ID>.lock` — тот же механизм, что у агентов:
пока не все писатели переведены на `tt`, замок обязан пониматься обеими сторонами.

**Пути по умолчанию нет.** Только `--vault` или `TT_VAULT`.

## Patterns to follow

- TDD: сначала падающий тест, потом минимальная реализация. Каждая задача плана так и устроена.
- Один файл — одна обязанность. Файл начал делать много — это сигнал, а не мелочь.
- Никакого рекурсивного удаления. `os.Remove` на пустой каталог замка — предел.
- Ошибки на русском, как и весь остальной вывод: инструмент однопользовательский.
- Никаких `panic` в библиотечном коде: ошибка возвращается вызывающему.
