# Tech Context

## Stack

- **Go 1.27** (в `go.mod` — `go 1.27.0`), почти целиком stdlib.
  Единственная зависимость: `gopkg.in/yaml.v3` (чтение фронтматтера).
  Планово добавится `fsnotify` на этапе 3 (вотчер файлов для сервера).
- **HTTP** — `net/http` с роутером из 1.22. Фреймворка нет и не планируется.
- **Живое обновление клиента** — SSE на голом `net/http`, не WebSocket: поток нужен
  односторонний, сервер→клиент, а команды идут обычным POST.
- **Фронтенд (этап 3)** — Svelte + Vite, бандл вшивается в бинарник через `go:embed`.
  `node_modules` нужен только для сборки и в артефакт не попадает.
- **Плагин Obsidian (этап 2)** — TypeScript + esbuild, отдельная папка `obsidian-plugin/`.

## Local development

Go установлен в `C:\Program Files\Go`, но **PATH текущей сессии его может не видеть**
(установка через winget не обновляет окружение уже запущенных процессов). Обходной путь
до перезапуска терминала:

```bash
export PATH="/c/Program Files/Go/bin:$PATH"
```

Команды:

```bash
go test ./... -race        # весь набор тестов с детектором гонок
go vet ./...
go build -o tt.exe ./cmd/tt
```

Путь к vault не имеет значения по умолчанию — только `--vault <путь>` или `TT_VAULT`.
Это сделано намеренно: молча писать в чужой каталог хуже, чем потребовать один флаг.

Рабочий vault: `D:/task tracker`. **Правки проверять на копии**, а не на живом vault.

## External integrations

Внешних сервисов нет: инструмент целиком локальный, сеть — только `127.0.0.1`
(и опционально LAN по явному `--listen 0.0.0.0` с токеном на изменяющие запросы).

Связь с vault — только через файловую систему:

- `<vault>/tasks/<project>/*.md` — таски, источник правды
- `<vault>/.task-tracker/schema.json` — общий контракт правил флоу
- `<vault>/.locks/<ID>.lock` — замки, общие с bash-агентами
- `<vault>/projects/<project>.md` — `id_prefix` и `next_id` для выдачи ID (этап 4)
