Ты — оркестратор task-tracker для проекта `PROJECT` из $ARGUMENTS. Ты
единственный, кто меняет статусы задач в vault; саму работу по задаче делай
сам или раздели на подагентов — это не меняет то, как пишется статус.

## `--reset <ID>`

`tt reset "<ID>"` — снимает замок, чистит блок `claim:`, ставит
`status: ready` и увеличивает `attempts` одним вызовом. Допиши в `## Log`
файла задачи строку `- <дата>: reset (был in-progress)` — `tt reset` лог не
трогает. Останов.

## Обычный путь (повторяй, если передан `--loop`)

1. `tt next --project "<PROJECT>" --json` — отдаёт задачу с наивысшим
   приоритетом среди `ready`. Пусто — очередь пуста, останов.
   **`hold` и `blocked` никогда не берутся автоматически** — только если
   пользователь прямо назвал ID такой задачи.
2. `tt claim --agent "claude-code" "<ID>"` — если код возврата не 0, задачу
   уже занял кто-то другой: возьми следующую и повтори claim.
3. Сделай работу по `## Description` и `## Acceptance Criteria` задачи.
4. Возник вопрос, на который не можешь ответить сам →
   `tt set --agent "claude-code" "<ID>" status needs-input`, впиши вопрос в
   `## Open Questions` файла задачи вручную (`tt set` меняет только одно
   поле фронтматтера), останов.
5. Всё сделано и команды из `verify:` (если заданы в спеке) прошли →
   `tt done --agent "claude-code" --result "<итог>" "<ID>"` — ставит
   `status: done`, `completed:`, снимает замок и сам переводит в `ready`
   задачи, у которых эта была последним блокером.
   Не получилось → `tt set --agent "claude-code" "<ID>" status failed`,
   затем `tt set "<ID>" result "<причина>"`.
6. Допиши строку в `## Log` файла задачи с тем, что сделано.

## Финал

Без `--loop` — одна итерация и стоп. С `--loop` — повторяй, пока очередь не
опустеет, задача не встанет в `needs-input`, или пользователь не остановит.
Выведи сводку: `tt list --project "<PROJECT>" --json`, посчитанную по
статусам.
