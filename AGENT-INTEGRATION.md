# Подключение к Claude Code и Codex

`tt` полезен сам по себе как командная строка и веб-доска, но главную
ценность даёт не это, а то, что ИИ-агент может сам разбирать очередь задач:
брать следующую `ready`-задачу, выполнять её и закрывать, не трогая ничего в
vault напрямую — только через `tt`. Эта инструкция — как подключить такой
режим к Claude Code и к Codex.

Ниже везде `<vault>` — каталог с `tasks/`, который ты указал при установке
(`tt config show` печатает текущий путь), `<project>` — slug проекта из
`<vault>/projects/<project>.md`.

## Общий принцип

Агент работает с задачами только через CLI `tt` (`tt new`, `tt next`,
`tt claim`, `tt done`, `tt set`, `tt reset`) — никогда не правит YAML
фронтматтер файла задачи вручную. Так гарантия «меняется ровно один ключ,
остальное не трогается» (см. README, «Гарантии записи») не зависит от того,
какой агент её вызвал.

И Claude Code, и Codex подключаются одинаково по сути: в проект (или
глобально) кладутся файлы-команды, которые говорят агенту, какую команду
`tt` вызвать на каком шаге. Разница — в формате и месте этих файлов.

## Claude Code

Слэш-команды — обычные markdown-файлы. Claude Code читает их из двух мест:

- `.claude/commands/` в корне репозитория — команда доступна только в этом
  проекте;
- `~/.claude/commands/` — доступна во всех проектах.

Готовые примеры лежат в этом репозитории, в `agents/claude/commands/`:
`tt-task.md` (создать задачу), `tt-work.md` (взять и выполнить следующую
`ready`-задачу), `tt-done.md` (закрыть задачу вручную). Скопируй их в один
из каталогов выше и подставь свой `<project>` в аргументы при вызове.

Claude Code перечитывает список команд при старте сессии — если он уже
запущен, начни новую сессию (или новый чат), чтобы файлы подхватились.

## Codex

У Codex нет каталога `.claude/commands` и нет хуков — модель ориентируется
на `AGENTS.md` в корне репозитория (читается как системная инструкция) и на
отдельный каталог с промптами:

```bash
mkdir -p ~/.codex/prompts
cp agents/codex/prompts/*.md ~/.codex/prompts/
```

Важно: Codex читает **только верхний уровень** `~/.codex/prompts/`, без
подпапок — сразу класть файлы туда, не в подкаталог. В `AGENTS.md` пропиши
путь к `<vault>` и, если проектов несколько, таблицу `slug → id_prefix`
(смотри `<vault>/CLAUDE.md`/`AGENTS.md`, раздел «Project Repos», как
образец формата).

После копирования перезапусти Codex — команды вызываются как
`/prompts:tt-task`, `/prompts:tt-work`, `/prompts:tt-done`.

## Чем отличаются

| | Claude Code | Codex |
|---|---|---|
| Где лежат команды | `.claude/commands/*.md` (проект) или `~/.claude/commands/*.md` (глобально) | только `~/.codex/prompts/*.md`, без подпапок |
| Как вызывается | `/tt-work` | `/prompts:tt-work` |
| Системная инструкция проекта | `CLAUDE.md` | `AGENTS.md` |
| Аргументы | `$ARGUMENTS`, `$1`… | `$1`…`$9`, `$ARGUMENTS`, `$ИМЯ` для пар `ИМЯ=значение` |
| Когда подхватывает новые файлы | при старте новой сессии | при перезапуске |

## Как проверить, что подключилось

**Claude Code**: открой чат в каталоге проекта и набери `/` — в списке
команд должны появиться `tt-task`, `tt-work`, `tt-done`. Для проверки по
существу вызови `/tt-task "Проверка интеграции" PROJECT=<project>` — должен
появиться новый файл в `<vault>/tasks/<project>/`, а `tt list --project
<project>` — показать его со статусом `ready`.

**Codex**: запусти `codex` и набери `/` — в списке должны быть
`prompts:tt-task`, `prompts:tt-work`, `prompts:tt-done`. Та же проверка по
существу: `/prompts:tt-task "Проверка интеграции" PROJECT=<project>`, и
затем `tt list --project <project>`.

**Если не подключилось:**

1. Проверь, что `tt` вообще виден в PATH и настроен: `tt config show` — должен
   напечатать путь к vault и источник (`флаг`/`переменная окружения`/`файл
   настроек`/`значение по умолчанию`), а не ошибку «command not found». Если
   не найден — почини PATH (см. README, разделы про установку на
   Windows/macOS).
2. Проверь путь и расширение файла — ровно `.md`, ровно в одном из
   перечисленных выше каталогов (для Codex — без вложенных подпапок).
3. Перезапусти агента: оба читают список команд один раз при старте.
4. Убедись, что vault настроен: `tt config show` должен показывать путь, а
   не «значение по умолчанию».
